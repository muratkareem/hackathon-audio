# AI Meeting Intelligence — Автономный ИИ-протоколист

Проект для хакатона. Решение представляет собой локальное приложение (100% Offline) для транскрибации, диаризации и протоколирования совещаний с использованием LLM.

## 👥 Команда (4 человека)
- **UI/UX & Features (2 чел):** Отвечают за директорию `frontend/` (интерфейс, отображение RAG-чата, выгрузка отчетов).
- **Core Functions (2 чел):** Отвечают за директорию `backend/` (Whisper, Pyannote/диаризация, локальная LLM, API).

---

## 📁 Структура репозитория (Monorepo)

Такая структура (монорепозиторий) идеальна для хакатона: весь код в одном месте, но команды не мешают друг другу.

```text
.
├── frontend/               # 🎨 UI/UX (React, Vue, Next.js, или Streamlit)
│
├── backend/                # 🧠 Core Functions (Python, FastAPI)
│   ├── api/                # Endpoints (маршруты API для связи с фронтендом)
│   └── core/               # Основная логика ИИ:
│       ├── transcription/  # Модули для Whisper / Faster-Whisper
│       ├── diarization/    # Разделение по голосам (Спикер 1, Спикер 2)
│       └── llm/            # Промпты и интеграция с Ollama / Llama
│
├── data/                   # 💾 Локальные данные (В Git не попадают!)
│   ├── audio/              # Тестовые аудиозаписи (MP3, WAV)
│   └── models/             # Скачанные веса моделей (Whisper, LLM)
│
├── docs/                   # 📄 Документация (API контракты, презентация)
├── .gitignore              # Игнорирование тяжелых файлов
└── README.md               # Этот файл
```

## 🔄 Правила работы с Git (Hackathon Flow)

Для быстрой и бесконфликтной работы в команде из 4 человек используйте следующую стратегию:

### 1. Ветки (Branches)
- `main` — **Только рабочий код**. Сюда сливаем готовые фичи перед демо.
- Создавайте ветки от `main` для каждой задачи.
    - **Формат названий:** 
      - Фронтенд: `ui/dashboard`, `ui/export-pdf`, `ui/rag-chat`
      - Бэкенд: `core/whisper-setup`, `core/speaker-diarization`, `api/summary-endpoint`

### 2. Как работать (Пошагово)
1. **Обновитесь перед стартом:** 
   ```bash
   git checkout main
   git pull origin main
   ```
2. **Создайте ветку для своей задачи:**
   ```bash
   git checkout -b core/whisper-setup
   ```
3. **Пишите код, делайте коммиты:**
   ```bash
   git add .
   git commit -m "feat(core): добавил загрузку модели Faster-Whisper"
   ```
4. **Отправьте ветку на GitHub:**
   ```bash
   git push origin core/whisper-setup
   ```
5. **Создайте Pull Request (PR):** 
   - На GitHub создайте PR из вашей ветки в `main`.
   - Попросите **хотя бы одного** члена команды (желательно из вашей пары) нажать *Approve*.
   - Слейте PR (Merge).

### 3. Советы для ускорения
- **Договоритесь об API (Контракт):** Прежде чем писать код, созвонитесь на 10 минут и договоритесь, в каком формате `backend` будет отдавать JSON для `frontend`. Запишите это в `docs/api-contract.json`. После этого фронтендеры могут делать заглушки (моки) и рисовать UI, пока бэкендеры пишут сложную ИИ-логику.
- **Не пушьте модели!** Веса Whisper или Ollama весят гигабайты. Папка `data/models/` и `data/audio/` уже добавлена в `.gitignore`.
- **Используйте Docker (Опционально):** Если есть время, добавьте `docker-compose.yml`, чтобы фронтендер мог одной кнопкой поднять бэкенд и Ollama у себя на ноутбуке, не настраивая Python-окружение.
